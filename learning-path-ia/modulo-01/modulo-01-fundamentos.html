Fundamentos de IA Aplicada

Los conceptos base para entender cómo funcionan los LLM, RAG y agentes — sin jerga innecesaria.

Objetivos de aprendizaje

  • Explicar qué es un LLM, embedding y token en tus propias palabras
  • Diferenciar entre prompting básico, few-shot, chain-of-thought y RAG
  • Identificar cuándo un problema necesita un agente vs. un flujo determinista
  • Configurar tu entorno local con Ollama + OpenWebUI
  • Ejecutar tu primer prompt estructurado y evaluar la respuesta

1. Conceptos fundamentales

¿Qué es un LLM (Large Language Model)?

Un modelo de lenguaje grande es una red neuronal entrenada con terabytes de texto para predecir la siguiente palabra (token) en una secuencia. No "piensa" ni "entiende" — calcula probabilidades estadísticas basadas en patrones aprendidos.

Tokens y ventana de contexto

Los modelos no leen palabras, leen tokens (fragmentos de ~4 caracteres en español). La ventana de contexto es cuántos tokens puede "recordar" a la vez (entrada + salida).

  • Llama 3.1 8B: 128k tokens contexto
  • Qwen 2.5 7B: 128k tokens contexto
  • Modelos mayores (70B+): mayor calidad, más VRAM

Embeddings (incrustaciones)

Vectores numéricos que representan significado semántico. Textos similares → vectores cercanos en espacio latente. Base de RAG (Retrieval-Augmented Generation).

Temperatura y parámetros de sampling

  • Temperature 0: Determinista, siempre el token más probable
  • Temperature 0.3–0.7: Balance creatividad/coherencia (recomendado para agentes)
  • Temperature 1+: Muy creativo, puede alucinar

2. Prompting efectivo

Estructura de un buen prompt (Pattern: ROLE-CONTEXT-TASK-FORMAT)

ROLE: Eres un analista de procesos senior con 10 años en automatización.
CONTEXT: Mi cliente recibe 50 leads/día por WhatsApp. Actualmente los clasifica a mano.
TASK: Diseña un prompt que clasifique: "venta", "soporte", "spam", "otro".
FORMAT: JSON { "categoria": "...", "confianza": 0-100, "razon": "..." }

Técnicas clave

  • Zero-shot: Instrucción directa sin ejemplos
  • Few-shot: 3–5 ejemplos input/output antes de la tarea real
  • Chain-of-thought: "Piensa paso a paso" — mejora razonamiento complejo
  • System prompt: Instrucciones persistentes de comportamiento (rol, tono, límites)

3. RAG y Agentes — Cuándo usar cada uno

RAG (Retrieval-Augmented Generation)

Pipeline: Consulta → Embedding → Búsqueda vectorial (top-k) → Contexto + Prompt → LLM → Respuesta.

Úsalo cuando: Necesitas responder sobre documentos propios (PDFs, Notion, web) sin reentrenar el modelo.

Agentes

Un agente = LLM + Herramientas (tools) + Bucle de decisión (ReAct: Reasoning + Acting).

Úsalo cuando: La tarea requiere múltiples pasos, decisiones condicionales, o acciones en sistemas externos (API, BD, n8n).

Flujo determinista (n8n sin LLM)

Úsalo cuando: La lógica es fija, predecible, y no necesita "juicio" (ej: mover fila de Sheets a Notion, enviar email).

Ejercicio guiado: Tu primer prompt estructurado en OpenWebUI

  1. Levanta Ollama + OpenWebUI localmente: 
    # Terminal 1: Ollama
ollama serve

# Terminal 2: OpenWebUI (Docker)
docker run -d -p 3000:8080 \
  -v open-webui:/app/backend/data \
  --add-host=host.docker.internal:host-gateway \
  --name open-webui \
  ghcr.io/open-webui/open-webui:main
  2. En OpenWebUI (http://localhost:3000), crea una cuenta admin
  3. Descarga un modelo ligero: ollama pull qwen2.5:7b (o llama3.1:8b)
  4. En OpenWebUI, ve a Configuración → Modelos y selecciona el modelo descargado
  5. Crea un System Prompt nuevo: 
    Eres un clasificador de tickets de soporte técnico.
Categorías: "bug", "feature", "pregunta", "acceso", "otro".
Responde SOLO en JSON: { "categoria": "...", "confianza": 0-100, "razon": "..." }
  6. Prueba con estos inputs y verifica la salida JSON:
    • "No puedo entrar a mi cuenta, dice contraseña incorrecta"
    • "Quiero que añadan modo oscuro a la app"
    • "¿Cuánto cuesta el plan enterprise?"
  7. Experimenta con temperature: 0 vs temperature: 0.7 y nota diferencias
